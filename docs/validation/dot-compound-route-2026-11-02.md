# Dot 新地址与队列设置验证：2026-11-02

## 现场与原因

通过当前 Windows 客户端的只读可访问性信息确认，v1.4.31 打开的 Dot 地址为 `/dots/<id>~<id>`，网页输入框已显示，但客户端仍显示“检查会话”“网页输入框正在加载”。未向该业务会话发送测试消息。

原有四处 Dot 规则只接受单段 ID。带 `~` 的页面被当作普通聊天，遗漏 Dot 专用的 composer、消息和工作状态选择器；会话注册、回复地址规范化与只读回复完成判定也不接受该新地址。

## 修复

- 保留旧的单段 Dot 地址，并接受一个非空 `~` 后缀。每段仍限定 1–128 个字母、数字、下划线或连字符。
- 完整两段保留为会话身份；同前缀不同后缀、不同账号的设置、草稿和队列独立。普通 `/c/` 地址规则没有放宽。
- 保留显式目标对查询、片段、外部域名和编码分隔符的限制；序列化到网页的识别函数仍自包含。
- 集成回归另外复现了下拉框空值问题：Radix 隐藏表单控件在选项尚未挂载时发出空值 change，覆盖受控的定时模式。Select 只转发当前选项内的值，父组件仍可显式设置空值显示 placeholder。
- 随包 Electron 从 44.4.1 更新至 44.10.1，修复已公开的运行时安全问题，包括[受损证书阻断](https://github.com/electron/electron/security/advisories/GHSA-jr5w-w6x2-84p9)。未使用 `npm audit fix --force` 或降级打包工具。

## 已完成检查

- 修复前新增路由单测 3 项失败，真实 DOM 的新地址被识别成 `chat`；修复后 surfaces 单测 6/6、DOM 操作回归通过。
- 下拉框快速回归在旧实现失败，捕获到模式变成空值而已保存队列仍为 interval，且 `tasks=[]`。修复后四次切换保持各自模式、保存状态和草稿。
- `npm run build` 通过，含类型检查；`npm test` 183 项及发布清单 1 项通过。
- 新 Electron 上的完整 `dot-interval-desktop.mjs` 通过，覆盖新旧地址、真实设置与队列输入框、同前缀不同后缀隔离、首条延迟、持续工作、逐条间隔、重启无突发/重发、暂停、Send/Stop 和人工草稿保护。
- 新 Electron 上的完整 `surface-queue-desktop.mjs` 通过，覆盖 Work 模式恢复、新地址的 Dot FIFO、忽略点击后的重试、回复/工作等待、重启保留发送凭据且不重发，以及相同地址的跨账号隔离。
- 新 Electron 上的 `stuck-view-recovery-desktop.mjs` 通过。
- 独立只读复核未发现必须修复项；全部 7 处 Select 调用均不使用合法空选项。

测试使用独立资料目录和离线页面。初次并行初始化新 Electron 时，文件锁及 GPU 启动错误导致两项测试未执行到业务步骤；运行时初始化完成后分别重跑完整通过，不放宽业务超时。
