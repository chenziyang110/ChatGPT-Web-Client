# “再试一次”对话加载错误兼容：2026-10-19

## 现象与原因

用户截图的 ChatGPT 页面显示“无法加载此 ChatGPT 对话”，操作文案为“再试一次”。本机安装包版本核对为 v1.4.31。现有错误标题规则可以匹配，但操作规则仅接受“重试”、`Retry`、`Try again`，因此未识别新的错误卡片。

该遗漏会使队列无法进入原有的对话加载恢复流程。普通页面若仍有未结束的子资源请求，还可能落入原生加载超时处理，遮住本来可手动重试的网页。仅凭截图无法确定远端对话请求失败的原因；兼容修复不代表服务端数据或网络问题已恢复。

## 修复范围

- 只在两处现有操作文案规则加入“再试一次”，保留旧文案。
- 保留主区、标题、可见性、消息引用、登录/验证、编辑器和生成状态的限制。
- 沿用普通会话不自动刷新、该会话拥有运行队列时才自动恢复的规则；不修改重试预算或发送收据逻辑。

## 验证

- 真实 Electron DOM 回归：旧实现遇到“再试一次”时 `loadFailure` 为 `undefined`，修复后为 `conversation`。
- 使用未修复的旧构建运行更新后的 `conversation-load-recovery-desktop.mjs --initial-only`，同样明确失败于 `loadFailure` 诊断断言。
- `node tests/page-operation-desktop.mjs` 全部通过，覆盖四种按钮文案，以及引用、隐藏内容、侧栏、首页、临时会话、登录验证、编辑器、Stop 和 streaming 的误判保护。
- `npm run build` 通过，含类型检查。
- `npm test`：180 项通过，另发布清单 1 项通过。
- `node tests/conversation-load-recovery-desktop.mjs` 完整通过，使用“再试一次”卡片验证普通页面不自动刷新、未完成子资源不遮盖网页、后台队列恢复、发送收据与防重发、反复失败和原生加载中断、暂停/取消、独立账号及健康标签页保护。未放宽既有超时、恢复预算或发送规则。
- 独立只读复核及 `git diff --check` 通过。

测试使用独立资料目录与离线页面，不向用户的真实会话发送消息、不清除登录资料，也不升级正在运行的安装版。这项修复在验证时尚未发布。
