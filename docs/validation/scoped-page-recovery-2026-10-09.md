# 按会话队列限定网页自动恢复

日期：2026-10-09。本文记录针对 v1.4.26 普通标签页反复自动恢复问题的源码调查、修复策略和本地验证。当前改动拟随 v1.4.27 发布；本文不代表生产客户端已安装或发布完成。

## 报告现象与根因

普通标签页没有会话队列。ChatGPT 显示“无法加载此 ChatGPT 对话”及“重试”按钮后，客户端数秒内用“页面暂时无法加载 / 操作未完成，请稍后重试”遮住网页，并反复恢复页面。

旧实现的调用链与该现象一致：

1. `BrowserRuntime` 每 1.5 秒检查所有存活网页。`ChatGPTAdapter` 在个人会话路径中识别真实、可见的错误卡片和 Retry 按钮，排除消息正文、侧栏、隐藏内容、登录验证页和仍在生成的回复；没有可用输入框时返回 `loadFailure = 'conversation'`。
2. `observe` 原先不检查该会话是否有自动队列，直接设置软件页面错误，并安排 `conversation_load` 恢复。`layout` 因错误状态隐藏原生网页，renderer 显示软件恢复界面，网站自己的 Retry 控件也随之不可见。
3. 首次恢复延迟 1 秒，随后按 2、4、8、16、30 秒退避，之后每 30 秒继续。此类语义错误绕过普通原生故障的 3 次恢复上限；恢复会重建原生 `WebContents`，并非仅等待网站自己的请求完成。同一目标后续发生原生加载失败或超时，也可继续这条会话恢复链。
4. 软件错误文本以 ASCII `ChatGPT` 开头，而 `friendlyError` 只直接保留以中文开头的简短提示，因而落入“操作未完成，请稍后重试”的通用文本。这解释了报告中的正文变化；此次修复通过保留普通网页避免显示该遮罩，没有扩大错误文本透传范围。

这里检测的是网页 DOM 中的会话错误，不是拦截网站 API 返回值。原生 `did-fail-load` 已明确忽略主框架 `ERR_ABORTED`（代码 `-3`）；不能把该语义恢复链直接归因于此错误码。未提交主导航、真实加载超时、渲染进程退出和无响应另有原生恢复路径。

相关源码：[`BrowserRuntime`](../../src/main/BrowserRuntime.ts)、[`ChatGPTAdapter`](../../src/main/adapters/ChatGPTAdapter.ts)、[`friendlyError`](../../src/renderer/errors.ts)、[软件恢复界面](../../src/renderer/main.tsx)。源码调查可以解释客户端为何覆盖网页及循环恢复，不能确定网站原始会话请求失败的网络或服务端原因。

## 最终策略

`AgentGateway.automaticRecoveryTasks()` 单独提供自动恢复资格，不再以账号存在、已登记会话或输入锁作为恢复授权。资格要求任务为待执行或执行中的 prompt，且明确提交；账号队列和会话队列均未暂停、未人工接管，同一队列没有等待用户决定或未确认的发送结果。浏览器操作和未提交草稿不授予资格。

`BrowserRuntime.hasAutomaticRecovery()` 同时匹配账号和任务所属网页或会话。普通标签页遇到网站会话错误或回复连接错误，且没有尚未提交的新主导航时，保留网站原文、原生页面和 Retry 控件，不新增软件遮罩、不自动重建。确有自动队列的会话仍可恢复同一目标，并保留已记录的发送回执，避免重放已提交消息。

`preserveSiteFailure()` 统一处理已确认可交互的网站错误页：标记当前原生页面可用，清除软件遮罩，终止语义恢复链及其计时器。观察、加载 watchdog 和实际重建前的检查都使用此处理，只有可见错误或加载状态发生变化时才更新布局和通知。

自动恢复资格在排程、异步页面检查和连接重置后的重建检查中重新核对。`setLocked` 收到任务状态更新时立即撤销已经失去资格的语义恢复链。真正的原生崩溃、无响应、未提交导航和无法完成的主加载仍保留原来的恢复机制与普通恢复上限；用户主动选择恢复页面仍可执行。

资格来源和接线：[`AgentGateway`](../../src/core/agent/AgentGateway.ts)、[`main.ts`](../../src/main/main.ts)。

## 源码审查覆盖

- 原生与语义错误的两个交接点：watchdog 已安排原生恢复后，网页在延迟期间出现可交互错误卡片，重建前检查会保留该网页；观察先于原生恢复计时器执行时，同时清除计时器和残留原生错误遮罩，避免取消恢复后仍隐藏网站。
- 未提交主导航：旧文档已显示网站错误卡片，而用户请求另一个会话的主导航失败时，不把旧卡片误当成新目标已经可用。观察中的普通网页保护已加入没有未提交导航的条件，此边界在源码中闭合；新目标继续走有恢复次数上限的原生故障路径，避免清除错误和计时器后丢失导航目标。
- 同地址刷新：活动检查返回后重新核对加载代次和当前加载状态，丢弃刷新前的旧错误快照，避免把新加载误标记为可用、吞掉其超时恢复。
- 取消、暂停和人工接管：任务变更同步刷新资格；已排程的语义计时器被撤销，正在等待页面检查或连接重置的恢复在后续检查中停止。确认结果尚未处理的队列不授权后继任务恢复页面。
- 同账号会话隔离：一个会话的自动队列不授权另一普通会话恢复；相同会话标识也需要匹配账号。连接池重置继续要求该账号只有一个存活网页且没有登录弹窗，保护同账号健康网页和其他账号。
- 待执行重试：任务退避期间即使暂时没有运行锁，仍保留自动恢复资格。恢复不局限于 `running`，因此已记录回执的待重试任务和未发送队列仍能继续。
- 原生故障：此次范围限制针对可交互的网站错误；没有可用 DOM 的崩溃、真正无响应或主导航阻塞仍走原生恢复。没有禁用全局活动观察和健康检查。

以上为源码审查结论。异步恢复资格撤销的每一种时序并未分别进行故障注入；实测结果与仍待完成的回归列于下表。

## 验证边界

此次没有重新授权真实用户账号，没有安装或重启用户正在使用的生产程序，也没有借用真实账号发送测试消息。隔离 fixture 可以验证客户端是否覆盖和重建网页、队列恢复资格及回执保留，不能证明真实 ChatGPT 服务端或用户网络故障已经消失。真实账号场景、打包结果和正式发布状态需要另外记录；此文档不代替这些确认。
