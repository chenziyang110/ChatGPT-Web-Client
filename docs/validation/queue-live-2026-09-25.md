# 会话队列真实网页验收：2026-09-25

## 环境与证据范围

Windows 上的 Electron 客户端，三个已登录账号，分别创建专用验收会话。直接读取真实 chatgpt.com 的 DOM、使用真实输入框和发送按钮、核对真实回复；未对这些账号拦截网络或替换网页。只发送验收短消息，停止测试使用独立的长回复请求。

原始 DOM、任务记录和用户数据备份仅保留在本机临时目录，不纳入仓库。下面的离线 fixture 是从所见结构提取的最小复现，不是真实网站截图，也不代替真实验收。

## 实际发现

旧版假定存在 `#prompt-textarea`、发送／停止按钮的 `data-testid` 和消息的 `data-message-author-role`。此次实际网页采用：

| 用途 | 实际观测结构 |
| --- | --- |
| 输入区 | `[data-chatgpt-composer] [contenteditable="true"][role="textbox"]` |
| 发送 | 输入区内 `button[type="submit"][aria-label="发送"]`，输入后异步出现 |
| 停止 | 输入区内 `button[aria-label="停止"]` |
| 轮次 | `[data-turn-key]` |
| 消息角色 | `data-chatgpt-search-unit-key` 的 `:user`／`:assistant` 后缀 |
| 消息标识 | `data-chatgpt-search-message-ids` |
| 正文 | `[data-user-message-bubble]`／`[data-chatgpt-selection-message-id]` |
| 完成操作 | `.turn-action-controls` 内的“复制”按钮 |
| 新会话过渡地址 | `/c/local-chatgpt%3A<uuid>`，随后成为正式 `/c/<id>` |

旧代码在实际可输入页面上返回“未找到输入框”，导致等待超时。先修复元素后，真实新会话测试又暴露临时地址误判；修复后重新验收。旧的“未发送失败也跳过”策略同时移除。

## 自动回归范围

新增 `modern-queue-desktop.mjs`，使用新的最小 DOM 结构覆盖延迟发送按钮、临时地址绑定、点击无效后的补点、输入异常后的同条重试、FIFO、多账号隔离，以及无法思考／连接中断／空回复停止后的继续。已有桌面回归保留旧 DOM、图片回复、页面恢复、标签恢复、队列编辑、账号隔离、更新安装等场景。

核心测试覆盖重试期间保持队首、其他会话继续执行、取消／暂停、旧自动阻塞状态迁移、保存发送记录后恢复观察而不再次输入。短观察期限恢复时留出完成状态所需的稳定窗口，避免反复超时而永远不能判定结束。

## 限制

没有人为触发真实服务端风控、登录失效、验证码或“无法思考”故障；这些状态通过离线回归验证，不宣称真实服务端全覆盖。临时异常自动重试不会绕过登录、验证码，也不会覆盖人工草稿。真实网页结构仍可能在以后改变。

已提交消息的恢复优先核对会话与消息标识。若服务端尚未显示提交结果且草稿也已消失，不能仅凭等待时长断言发送失败并重复提交。正常生成期间不主动停止远端任务。人工暂停／接管与自动故障恢复分开处理。
