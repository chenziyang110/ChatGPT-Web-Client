# Work / Your dot 会话队列验证

日期：2026-09-30。

## 实现与实际网页结构

Work 首页和聊天首页都使用 `https://chatgpt.com/`。只识别输入框不能保证发送模式；新队列保存 `surface: work`，刷新或重建首页后选择真实「工作」按钮，再核对输入框模式、地址、用户消息历史和草稿后发送。已绑定的 Work 会话继续使用其原 `/c/<id>` 地址。

Your dot 使用 `/dots/<id>` 和 `[data-codex-composer-root]`，没有表单。它的发送控件是 `type=button`、带 Send/发送标签的按钮。消息使用 `article.message-row[data-message-id]`，用户行具有语义类 `self`，正文位于 `.message-body[data-message-id]`。回复操作位于 `.message-inline-actions--orbit`，不使用聊天页的复制按钮。

Dot 的「Pause your dot」控制后台 Agent 活动，不能当成单条消息的 Stop 控件。队列等待发送之后的新回复与稳定的消息操作；可用输入框和持续后台活动都不能独自证明当前回复结束。发送前的回复标识保存在回执中，避免把历史主动消息误当成新答复。

每个账号和会话保持独立队列。Dot 地址复用时按账号隔离；`/c/<id>` 与 `/dots/<id>` 即使路径末尾相同也不共享标识。主页切换模式时，面板自动重新绑定，并在加入消息时再次核对页面；原队列草稿保留。

## 真实账号验证

在用户授权的已登录账号中使用无工具、无设置变更的短提示词。首次结构检查使用专门新建的验收会话，随后使用同一账号分区的独立隐藏测试视图，避免用户切换可见页面影响验证。没有导出登录凭据、复制浏览器资料或发送到其他用户会话。

- 实际 Work 首页选中工作，首条消息生成真实会话地址；项目适配器自动恢复 Work 模式并串行发送两条消息，两次都记录一次发送意图、确认提交、得到对应的完整标记回复。
- 项目适配器在实际 Your dot 中串行发送两条消息，均完成并自动推进，未重复点击发送。
- 实际 Dot 会替换刚发送的用户消息 UUID。对已确认提交但身份关联丢失的答复，返回 `responseUnavailable`，在该固定频道出现新的稳定回复后继续下一条，不冒充已匹配的答案，不重发旧问题。
- Dot 回执恢复另行中断并重建本地观察器，继续读取原回复后再发送下一条，验证不重放发送动作。

## 自动化回归

`tests/surface-queue-desktop.mjs` 在独立测试资料目录中运行真实 Electron 进程，网页为按上述 DOM 构建的离线替身，覆盖：

- 面板已打开时主页从 Chat 切换 Work，队列标识及草稿分开。
- 首页刷新后默认 Chat，执行原 Work 队列时自动恢复 Work，按 FIFO 发送。
- Dot 发送点击首次被忽略，仅在原草稿及历史未变时重试。
- Dot 尚未回复时即使 Send 可用、后台 Pause 控件存在，也不会发送下一条。
- Dot 用户消息从临时 UUID 更换为服务器标识。
- 完全退出并重新启动 Electron，恢复原发送回执，等待回复后继续，不重发。
- 两个账号打开完全相同的 Dot 地址，消息及队列互不影响。

另有会话模式/地址/答复读取的核心测试，以及既有 Chat/Work 新版 DOM 队列、首页就绪、错误结束、发送回执和跨账号回归。桌面替身与真实账号测试分开陈述；未声称覆盖未来所有网页更新或所有后台工具执行方式。
