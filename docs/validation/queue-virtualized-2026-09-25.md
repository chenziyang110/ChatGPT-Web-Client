# 长回复队列卡住：2026-09-25

## 真实故障证据

在用户报告的已登录 v1.4.15 客户端，通过本地认证诊断接口读取实际卡住会话：

- 任务已有 `submittedAt` 和稳定 `submittedMessageId`，正在等待回复。
- 页面 `readiness=ready`，输入框存在，草稿为空。
- `busy=false`、停止按钮、流式生成及当前回复忙碌标记均不存在。
- DOM 中只剩 1 条 assistant 消息，完成操作已出现；提交的 user 消息已被网页卸载。

`awaitReply` 当时要求提交的 user 元素仍在 DOM，才允许检查结束，所以页面已完成也无法推进。短消息和仅卸载历史前缀的旧测试没有覆盖这一情况。

## 修复范围

后台会话队列保留已确认提交状态。若提交的 user 元素被卸载，原会话、可用空输入框和无生成状态连续稳定 6 秒，结束本轮并推进；只剩带完成操作的 assistant 时记录完成，没有完整答复时按中断结束并继续。

这种完成记录不伪造回答归属：返回 `responseUnavailable=true`，不返回未经关联的回答或通知令牌。普通 Agent 回答读取继续要求严格身份匹配。主动接管和暂停不被自动解除。

## 回归证据

- 新增恢复测试在旧实现下超时失败，修复后通过：只读观察，不补发已确认提交的消息。
- 覆盖生成中、页面加载、无输入框、有草稿、无提交确认、目标会话变化、新增其他提问。
- Electron 离线 DOM 回归在提交确认后删除 user 元素，并覆盖停止时整段消息元素消失：确认完成及中断均推进下一条，发送记录恰好三条且各一次。
- 发送后重新加载旧提问的边界回归使用发送前 assistant 的稳定标识，不把其之前的同文问题视为本次发送；发送记录只新增该回复的标识，不重复保存回复正文。
- 核心测试、发布清单测试和 Agent 测试通过；依赖审计 0 个已知漏洞。完整桌面回归覆盖 20 组场景，随后变更另重跑关联测试。

离线 DOM 回归用于稳定重现实际观察到的结构，不代表已完成新版登录会话的现场验收。现场验收结果应在运行修复版后补充。
